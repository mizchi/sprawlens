# Sprawlens formalization

Sprawlensの実行実装はTypeScript / JavaScriptに置き、ここでは論文の中心contractを実装詳細から独立したLean 4の定理として管理する。LeanからJavaScriptを生成せず、手書きTypeScriptとの対応は`claims.json`と共有conformance fixtureで監査する。

## Pinned environment

- Lean: `v4.33.0`
- Mathlib: `v4.33.0` (`db584cd6d46c92f209a44c0f1c829460d327499d`)
  - L0の抽象relationとL1–L2はMathlib非依存。
  - 実行可能な有限selector、exact rational adjacency slack、L3のfinite geometry / algebraに使用する。

## Commands

```bash
just lean-check
just lean-conformance
```

`lean-check`は定理をmachine-checkする。`lean-conformance`はそれに加えて、
`TestVectors/feasible-envelope.json`、`TestVectors/external-sequence-gate.json`、`TestVectors/temporal-barycenter.json`、`TestVectors/orientation.json`、`TestVectors/proper-segment-intersection.json`、`TestVectors/point-in-open-segment.json`、`TestVectors/collinear-open-overlap.json`、`TestVectors/simple-open-ring.json`、`TestVectors/polygon-signed-area.json`、`TestVectors/half-plane-boundary-parameter.json`、`TestVectors/half-plane-edge-classification.json`、`TestVectors/half-plane-clip-fold.json`、`TestVectors/segment-interpolation-orientation.json`をLean executableとTypeScriptの純粋関数の双方で実行する。

## Current model

`Sprawlens.FeasibleEnvelope`はcandidate、constraint score、selection costの具体型を仮定しない。有限候補集合、validity predicate、複数constraint floor、cost最小性、baseline fallbackだけを扱う。

baselineがeligibleなら、任意のselection resultについて次を証明済みである。

- selected candidateは宣言した有限集合の要素である。
- selected candidateはvalidである。
- selected candidateは全constraint floorを満たす。
- selected costはbaseline cost以下である。

eligible集合が空の場合はbaselineへfallbackする。baseline自身がinvalidならresultもinvalidになりうるため、「全resultがvalid」は成り立たない。この反例をLean file内のwitnessとして保持する。

`Sprawlens.FeasibleEnvelopeSelector`は、costとtie-break keyの全順序から有限候補を決定的に選ぶ実行可能関数を定義する。eligible候補があればその最小要素、なければbaselineへfallbackし、その戻り値が常に上記abstract relationの`IsResult`を構成することを証明した。共有fixtureを読むLean checkerもこのselectorを使う。TypeScriptのsort実装全体、candidate生成、solver convergenceの正しさを証明したものではない。

`Sprawlens.Paper1Contract`はこの一般relationと実行可能selectorを第一論文のprimary policyへ特殊化する。candidateはexact rational adjacency、exact rational displacement、convergence flagを持ち、zero-tolerance adjacency floorとdisplacement costを使う。baseline membershipとbaseline convergenceの下で、selectorが返すcandidateの収束、baseline以上のadjacency、baseline以下のdisplacementを個別に証明した。論文中のdominance contractはこの三定理に対応する。

`Sprawlens.AdjacencyRate`はTypeScriptの`realizedEdgeRate`を、eligible edge数とrealized edge数のexact rational比としてモデル化する。比較用の数値slack `10^-12`が一辺分のscore量子より小さければ、slack付き判定を通ったcandidateはbaselineよりrealized edge数を減らせない。したがって両candidateが同じ正のeligible edge分母を持ち、その分母が`10^12`未満なら、この離散的な非劣化を証明できる。TypeScriptでは分母計算を`eligibleEdgeCount`へ分離し、同じedge listとnode domainならcandidate geometryに依存しないことを回帰testで固定した。分母がちょうど`10^12`なら一辺の損失がslackと同値になる反例も保持する。これはIEEE-754演算一般のrefinement proofではない。

`Sprawlens.ControlledPaths`は第二論文のcontrolled sequenceを離散graphとして一般化する。no-op / reversalの始終端同値性、weight変更とleaf追加、weight変更とedge rewireの可換性を証明した。graphはlistで保持するため、AB/BAの終端同値性はnode、weight、edge、request orderの完全一致である。これは同じ入力graphへ至ったlayout geometryが一致するという主張ではなく、その差をpath dependenceとして識別できるための前提だけを証明する。

`Sprawlens.ExternalSupport`はrequest / frozen capabilityからのexpected-support判定、responseのtotal classification、confirmatory effect gateを扱う。expected-supportedへの`unsupported`とexpected-unsupportedへの`ok`をそれぞれfailureへ分類し、一つでもpath gateが落ちればeffectを生成できないことを証明した。TypeScript側では`externalSequenceGate.ts`を純粋moduleとして分離し、探索用`calibration`と全gate通過後の`confirmatoryEffect`を別フィールドにした。

`Sprawlens.TemporalBarycenter`はfinite weighted centerとUIで使う2点のhistory mixを、座標型や次元に依存しないmoduleとして扱う。index relabeling、translation、uniform scaleに対する不変性と、非負weight・正の総weightでconvex hull内に入ることを証明した。TypeScript側の`barycenter.ts`はIEEE-754実装なのでbit-level permutation invarianceは主張せず、6ケースの有理数fixtureとtolerance testで対応を監査する。この標準的なaffine性質自体は論文の新規性に数えない。

`Sprawlens.ExactGeometry`はpolygon判定の基礎となる2次元orientation determinantをordered field上で定義する。translation invariance、uniform scaleに対する二次性、巡回置換・反転、strict left turnなら3点が相異なることを証明した。TypeScript側ではpolygon validityとconvex hullが同じ`orientationDeterminant`を使い、6ケースの整数座標fixtureをLeanの有理数modelと共有する。これは標準的な計算幾何の基礎であり、新規性ではない。また、simple polygon、self-intersection、clipping、面積保存まで証明したことを意味しない。

`Sprawlens.SegmentIntersection`は、二本のopen segmentの内部が横断するproper intersectionを、双方のorientationがstrict opposite signsになる関係として定義する。segment交換、各segmentの端点反転、translation、非ゼロuniform scaleに対する不変性と、proper intersectionなら四つの端点を共有しないことを証明した。実行可能なBool判定器と論理predicateの同値性も証明し、TypeScriptと8ケースを共有する。端点接触と共線重複は意図的にこのpredicateから除外する。epsilon付きの近似判定、polygon edgeの隣接関係、ring全体のsimple性はまだ証明対象ではない。

`Sprawlens.SegmentContact`は、点がsegmentと共線で、少なくとも一軸で端点間に厳密に入り、他方でも閉区間内にあることをopen-segment membershipとして定義する。端点反転、translation、正負を含む非ゼロuniform scaleに対する不変性、membershipによる端点・退化segmentの排除、Bool判定器との同値性を証明した。TypeScriptのdominant-axis実装とは11ケースのexact整数fixtureを共有する。floating-point toleranceの完全性・健全性は証明していない。

`Sprawlens.CollinearOverlap`は、二本の非退化segmentについて、一方の端点が他方のopen segment内部にあるか、両segmentが同一または反転同一であることを、open interiorsが正の長さで重なるexact relationとして定義する。実行可能Bool判定器との同値性、segment交換対称性、非退化性、同一・反転segmentの包含を証明し、TypeScriptのinterval実装と10ケースを共有する。min/max実装全体やfloating-point toleranceの一般証明ではない。

`Sprawlens.SimpleRing`は最低3頂点を型で保証するcyclic index、edge successor、隣接edge関係を定義し、頂点のinjectivity、全edgeの非退化、全非隣接edge pairでproper crossing・open-segment contact・collinear overlapがないことをtopological simplicityとする。segment conflictのBool判定器との同値性、edge隣接の対称性、simple ringから各無衝突条件が得られることを証明した。TypeScriptのcyclic pair走査とは8ケースのring fixtureを共有するが、走査実装全体の一般同値証明ではない。convexityとwinding directionはこのcontractに含めない。

`Sprawlens.PolygonArea`は有限index集合とcyclic successor permutation上のshoelace sumをsigned twice-areaとして定義する。translation invariance、uniform scaleに対する二乗則、successor反転による符号反転、三角形ではorientation determinantと一致することを証明した。さらに三角形の両端を隣接edge上の補間点へ置換した局所面積が`(1-s)t`倍になることを示した。TypeScriptでは既存`signedArea`を`signedTwiceArea / 2`として再構成し、符号、translation、scale、退化列を含む9ケースを共有する。このprimitive単独からclipping ring全体の面積単調性を主張せず、後段の`ConvexClipArea`で必要な幾何条件とemitter対応を合成する。

`Sprawlens.PolygonAreaRewrite`はmaterialized listのopen / cyclic shoelace和を定義し、cornerを隣接二辺上の補間点へ置換した面積差が切除triangleのsigned twice-areaにexactに一致することを証明する。parameterが`[0,1]`で元turnが非負なら面積は増加しない。cyclic rotation不変性、長さ2以下で面積0、`List.Triplewise`のCCW列で面積非負、中間頂点と連続chainの削除で面積非増加を証明した。さらにinside終端、outside chain、inside始端からなるcanonical mixed clipを、outside中間chain削除と二つのboundary intersection置換へ分解し、全体の面積非増加まで合成した。隣接重複の`destutter`と明示的closing duplicateの除去がshoelace面積を変えないことも証明し、emitter正規化を面積証明から分離した。

`Sprawlens.ConvexClipArea`はstrict global vertex orderから入力shoelace面積の非負性を導き、実際の`clipIndexedRing`について任意のclosed half-planeでsigned twice-areaが増えない無条件定理`clippedSignedTwiceArea_le`を証明する。四点のaffine circuit恒等式から得たoutside / insideの巡回連続性を`IsRotatedBlock`へ変換し、頂点列を回転して`List.ofFn`のindexed edge列とideal emitter flattenをcanonical decompositionへmaterializeした。全inside、全outside、one-inside、one-outside、一般mixedを分け、実emitterの`destutter`とclosure正規化が面積を保存することを介して最終ringへ接続する。旧general mixed certificateが両singleton caseを表現できないことは三角形のLean反例として保持し、既存の`ClipAreaCertificate`経路も検査可能な補助contractとして残した。未証明なのは、このexact ordered-field modelとTypeScript floating-point実装全体とのrefinementである。

`Sprawlens.HalfPlaneIntersection`は、二点の符号付き距離をaffine補間して半平面境界と交わるparameterを定義する。内側から外側、外側から内側の双方について分母の非零性とparameterが`[0, 1]`に入ること、得られる補間距離がexactに0になることを証明した。座標補間も共通primitiveとし、補間点を三角形の始点・中間点・終点へ入れたorientationが元determinantの`1-t`または`t`倍になることに加え、両外側頂点を補間したturnが`(1-s)t`倍になり非負性と元turn以下の大きさを保つことを証明した。さらに三頂点それぞれを任意のsegment上で動かすため、orientationの各引数に対するaffine則を分離した。TypeScriptでは実際の交点生成がこのprimitiveを使用し、境界parameter 6ケースとorientation 5ケースを共有する。ring全体のorientation保存とclipping後の面積境界は後続contractで扱う。

`Sprawlens.HalfPlaneClipStep`は、oriented edgeをclosed half-planeに対してinside / leaving / entering / outsideへ全分類する。各classと二点の符号条件の同値性を証明し、leaving / enteringからboundary parameterの`[0, 1]`包含を導いた。一辺が出力する符号付き距離列を最小modelとし、長さが最大2、重複なし、全要素が半平面内であることを証明した。`Sprawlens.HalfPlaneClipPoints`はこれを実際の2次元point emitterへ具体化し、距離modelとの一致、全出力点の半平面内包性、全点が元edgeのclosed segment上にあることを証明する。各出力点に対応するedge parameter列も定義し、point列との一対一対応、全parameterの`[0,1]`包含、出力順での単調性を証明した。共有fixtureのLean checkerも再実装した距離関数ではなく、このpoint emitterを実行する。TypeScriptの`clipHalfPlane`も同じ分類・step emitterを使用し、境界端点と期待出力を含む8ケースを共有する。

`Sprawlens.HalfPlaneClipFold`は複数edgeのstep出力をflattenし、隣接重複を除いて連結する。正規化結果が元のflatten列のsublistであること、隣接要素が相異なること、全出力距離が半平面内に残ることを証明した。`Sprawlens.OrderedTriples`では、単なる連続三点条件が一般のsublistで保存されない反例を固定し、Mathlib標準の`List.Triplewise`をproject contractとして公開する。この強いcontractはsublistと`destutter`で保存され、正規化後の全連続三点の非負orientationを導く。flattenの義務を各chunk内とchunk境界へ分離し、edge pair / triple supportから双方を合成した。さらにcyclic ring固有の義務をopen-chain turnと二つのwrap turnへ分け、orientationの巡回置換不変性により`AllOrderedCCW`だけからwrap turnも導いた。TypeScriptでは`cyclicRingOutput.ts`へfold責務を切り出し、step境界をまたぐ重複と非隣接の再出現を含む6ケースを共有する。

`Sprawlens.SegmentTripleOrientation`は、三つのoriented segmentの各端点8組がweak left turnなら、各segment上の任意のconvex補間点三つもweak left turnであることを証明する。同じsegment上の二点についてはparameter差でorientationがscaleされ、emitterがparameter順を保つことから向きが反転しない。edge列のpairwise supportとtriplewise traversal supportから、実際の`flatMap outputPoints`全体が非負orientationの`Triplewise`を満たす合成定理も得た。支持半平面のpair条件だけではedge順序を表現できず、三角形のedgeを並べ替えるとpair条件を保ったままtriple条件が壊れる反例を固定した。これによりedge間の幾何、巡回順序、flattenのlist bookkeepingを分離した。この補題群は標準的なaffine geometryであり、論文の新規性には数えない。

`Sprawlens.CyclicClosure`は、open ring表現で末尾が先頭を明示的に繰り返す場合だけ末尾を一つ除く。空列・singleton・open列の保存、closing branchでの`dropLast`選択、長さと要素predicateの保存を証明した。正規化結果が入力のsublistであることも証明し、隣接非重複、要素predicate、順序付き三点の非負orientationを保存する。異なる先頭二点のprefixと末尾二点のsuffixは`destutter`で保存される。さらに先頭と末尾が異なる非退化caseではclosureも両方を同時に保存するため、正規化前flatten列のentry / leaving pairを最終point ringへ移せる。共有fold fixtureはclosure前後の期待列を双方で検査する。

`Sprawlens.HalfPlaneClipRing`はpoint emitterを複数edgeのfoldとcyclic closureへ持ち上げる。正規化後の全出力点が半平面内にあり、元ringのいずれかのedge上に由来し、隣接重複と明示的closing duplicateを持たないことを証明した。さらに正規化前のflatten列が順序付き三点の非負orientationを満たすなら、foldとclosure後のopen-chainだけでなくcyclic ringの全turnも非負になる。strict entering / leavingと、その後のoutside edgeが空chunkを出すことからflatten境界pairを導く補助経路も証明した。距離だけをfoldすると、異なる二つの境界頂点がともに0となってcut boundary edge自体を失う反例も保存した。このためorientationと面積の後続証明ではpoint ringを正本とし、距離foldを使わない。

`Sprawlens.HalfPlaneBoundaryGeometry`はhalf-plane境界の接線方向を、内側が左に残る向きとして定義する。crossing signだけではseam順序が決まらない反例を保持し、leaving edgeに対してentering edgeの両端が左側にあるというconvexity条件を追加した。この条件から二交点が正しいexit→entryの`OrderedBoundary`を満たし、cut seam両端のturnがともに非負になることを証明した。この二つのturnは、強い`AllOrderedCCW`を仮定できない場合の補助的なwrap contractへ接続されている。

`Sprawlens.ConvexClipContract`は最低3頂点の`Fin` index上で、全頂点が全directed edgeの左側にあることをweak convex CCW contractとする。この全称条件から局所turnの非負性、全indexed edge pairのsegment support、任意のleaving / entering edge pairの正しい境界順序と非負seam turnを導いた。`List.ofFn`でmaterializeしたedge列では各edgeの終点が次edgeの始点に一致することも証明した。さらにindex順の任意三頂点がweak left turnになる`IsLinearlyOrderedCCW`を、materialized頂点列の標準`List.Triplewise`と同値な中間contractとして導入した。この頂点contractは、通常辺と最終頂点から頂点0へ戻るwrap辺を含む全directed edgeのsupportを含意する。さらに隣接edgeでendpointが一致するcaseを含む全8 endpoint選択を処理し、edge列のtriplewise traversal supportを導いた。3・4・5頂点ringでは逆向きにweak supporting-half-plane条件からlinear vertex orderまで直接証明済みである。5頂点以下では任意の三頂点に必ず循環隣接pairが含まれる。隣接二辺のsupportからshortcut chordのorientationに対する下界を与える恒等式も証明したが、その下界は負になりうる具体反例をLeanで固定した。さらに6頂点では、同じCCW三角形を2周する列がweak contractを満たす一方、index順の三点`0,2,4`は右turnになる反例を証明した。したがってweak supporting-half-plane条件だけからglobal vertex orderを導く一般定理は偽であり、主経路は明示的なglobal orderを正本とする。`Sprawlens.StrictConvexContract`はこの正本を全index順三点のstrict left turnへ強め、weak order、全辺support、clipping後のcyclic turn非負性を順に導く。strict contractはsupport条件を重複保持しない。一方、`Sprawlens.HexagonChord`では除算なしのchord frameで6頂点の二つの非隣接三点を解析し、右turnなら三頂点周期の重複が必ず生じることを証明した。このため6頂点では頂点injectivity、したがって`IsSimpleRing`を追加すればglobal orderを導け、clipping後の全cyclic turn保存まで接続できる。主経路ではcrossing index・flatten境界整列・交点相異性を追加仮定しない。strict crossingとedge列分解から同じ結論へ至る補助経路も残している。未証明なのは、7頂点以上でweak supportとinjectivityまたはsimple-ring条件からglobal orderを導く一般化、補助経路の境界退化case、およびTypeScript実装全体とのrefinementである。

shoelace総和への主経路は、inside/outside頂点の巡回連続性、`List.ofFn` indexed edge列へのmaterialization、ideal emitter flattenのcanonical decomposition、emitter正規化の面積保存を合成し、明示的なmixed decomposition証明書を入力に要求しない形で完了した。`ClipAreaCertificate`は局所分解を個別に検査する補助経路として残すが、境界重複を含む任意入力でその正規形を構成することは主定理の前提ではない。

加えてstrict global orderから任意の二頂点の相異性と`Function.Injective vertex`を導いた。したがって主経路ではinjectivityも別の入力仮定として要求しない。

## 証拠の境界

- Lean theorem: 抽象modelの全入力に対する証明。
- 共有fixture: 現在のTypeScript実装とLean executableが選んだ結果の有限例での一致。
- TypeScript unit test: controlled path builderが具体例でexact endpointを作る回帰検査。

したがって、共有fixture通過をTypeScript実装全体の形式証明とは呼ばない。
